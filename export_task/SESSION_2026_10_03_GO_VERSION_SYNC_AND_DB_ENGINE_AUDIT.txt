2.2 Fix Go Version Mismatch — HOÀN THÀNH
-----------------------------------------------------------------------------
Vấn đề phát hiện:

  Service                  | go.mod cũ    | Dockerfile builder cũ | Lỗi
  -------------------------+--------------+-----------------------+------------------------
  dataops_backend_api      | go 1.25      | golang:1.21-alpine    | go.mod requires >= 1.25
  dataops-stream-producer  | go 1.26.0    | golang:1.21-alpine    | go.mod requires >= 1.26

  QUAN TRỌNG: go 1.25 và go 1.26.0 là các version CHƯA TỒN TẠI tại thời điểm
  commit — đây là giá trị sai được đặt từ trước, không phải future version.

Root cause phân tích qua dependency chain:
  - github.com/redis/go-redis/v9@v9.22.0  → yêu cầu go >= 1.24
  - golang.org/x/net@v0.59.0              → yêu cầu go >= 1.26.0
  → Toàn bộ dependency graph bắt buộc Go runtime tối thiểu là 1.26

Giải pháp áp dụng: Cách B — Nâng image lên golang:1.27-alpine
  Lý do: Go 1.27.1 là stable release mới nhất, thoả mãn toàn bộ constraint.
  Không hạ version dependency vì sẽ phá vỡ tính năng.

Files đã thay đổi:

  dataops_backend_api/Dockerfile      FROM golang:1.21-alpine → golang:1.27-alpine
  dataops_backend_api/go.mod          go 1.25  → go 1.27
  dataops-stream-producer/Dockerfile  FROM golang:1.21-alpine → golang:1.27-alpine
  dataops-stream-producer/go.mod      go 1.26.0 → go 1.27

Lưu ý verify:
  - Local Go runtime là 1.23.1 → `go build` local cố tải toolchain 1.27 → timeout.
  - Không cần verify local. Build thực tế chạy trong Docker container trên Ubuntu.

4. BÀI HỌC KỸ THUẬT (LESSONS LEARNED)
=============================================================================

[1] Go Dependency Chain Constraint:
    Khi chỉnh go.mod version, không thể chỉ nhìn module chính — phải kiểm tra
    toàn bộ indirect dependency graph:
      go-redis/v9@v9.22.0  → go >= 1.24
      x/net@v0.59.0        → go >= 1.26
    Rule: Chạy `go mod tidy` sau khi thay đổi go directive để phát hiện conflict sớm.

[2] Không verify `go build` local khi go.mod > local runtime:
    Go toolchain tự động cố tải version mới về → timeout trong môi trường hạn chế.
    Dùng Docker build trực tiếp làm CI gate trong trường hợp này.

[3] PostgreSQL trong requirements.txt KHÔNG phải DB engine của dự án:
    psycopg2-binary + asyncpg là transitive dependency của Prefect orchestrator.
    Không nhầm lẫn khi đọc requirements.txt. Market data luôn đi qua MinIO/Delta Lake.

[4] go.mod version phải là version ĐÃ RELEASE thực tế:
    Khai báo go 1.25 hay go 1.26.0 khi chưa release sẽ gây lỗi build silently.
    Luôn kiểm tra https://go.dev/dl/ trước khi đặt directive.
